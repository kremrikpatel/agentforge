## Objective
Build Phase 1 of "AgentForge" — a production-grade, enterprise multi-agent AI platform. Phase 1 delivers the core agent execution engine: a 4-agent LangGraph pipeline (Analysis → Develop → Test → Deploy) that processes any input topic end-to-end, routed through an LLM gateway with provider fallback, basic guardrails, and a three-tier memory system. This is the foundation later phases (RAG, connectors, red-teaming, UI, K8s deploy) build on top of.

## Context
Full platform vision (for architectural awareness — do NOT build these yet, only Phase 1 below):
- **Agent execution core**: planning loop, tool dispatch, memory integration, error recovery — architectures ranging from single-pass ReAct to an iterative multi-plan executor.
- **LLM Gateway**: TensorZero-based, with Claude → GPT-4o → Gemini → Groq fallback chain.
- **Guardrails**: guardrails-ai + NVIDIA NeMo Guardrails, applied to every request.
- **Memory**: Redis session memory (STM), pgvector long-term memory (LTM), semantic caching layer.
- **Evaluation**: LangSmith LLM-as-judge scoring on every generated report.
- **Red teaming**: PyRIT-based dashboard running jailbreak, XPIA, crescendo, and skeleton-key attacks continuously.
- **RAG layer**: hybrid search + reranking + HyDE + CRAG + Self-RAG + Text2SQL (with human approval) + 9-layer guardrails pipeline, on Qdrant + PostgreSQL + Redis.
- **Connectors/Actions**: admin-configured actions calling real third-party APIs (Shopify, Stripe, etc.) and other agents, with retries, timeouts, schema validation, graceful degradation.
- **Admin UI**: open-webui-style frontend for configuring agent instructions, knowledge articles, and actions.
- **Instrumentation**: capture full execution trajectories (reasoning steps, tool calls, outcomes, implicit reward signals) for downstream model training.
- **Security/compliance**: PII filtering, audit logging, action versioning, governance bounds.
- **Monitoring**: Arize AI, LangWatch, LangSmith observability.
- **Infra**: Kubernetes, Docker, Helm — production provisioning throughout.

Backend language: Python. No existing codebase — this is a greenfield build.

## Target State (Phase 1 only)
A runnable Python backend where:
- A LangGraph state graph implements 4 Parellel agent nodes: Analysis → Develop → Test → Deploy, each with a distinct system prompt and typed input/output schema (Pydantic). and this agents talks with each other as Agent Team coordination.
- Any topic/task string submitted via a FastAPI endpoint flows through all 4 nodes and returns a structured final report, contract between agents plus per-node intermediate outputs.
- An LLM gateway module abstracts model calls with a configurable fallback chain (Claude primary, GPT-4o secondary, Gemin tertiary, Groq) and retries on failure/timeout.
- A Advance REGEX + ML + LLM based guardrails layer validates input and output (PII/prompt-injection/toxicity checks) before and after each agent node.
- Three-tier memory is wired in: Redis for session-scoped STM, pgvector (via Postgres) for LTM, and a semantic cache that short-circuits repeated/similar requests.
- Structured logging captures each node's reasoning trace, tool calls, latency, and success/failure for future instrumentation.
- Unit tests cover the graph's routing logic, the gateway fallback behavior, and the guardrails pass/fail paths.
- Docker Compose spins up the full stack locally (API, Redis, Postgres+pgvector) for local dev — full K8s/Helm manifests come in a later phase.

## Acceptance Criteria
- [ ] `docker-compose up` starts API + Redis + Postgres(pgvector) with no manual steps
- [ ] agents talks with each other as Agent Team coordination visualization on web ui
- [ ] `POST /pipeline/run {"topic": "..."}` returns a structured JSON report with output from all 4 agent stages contract between agents
- [ ] Killing the primary LLM provider (env var unset/invalid) triggers automatic fallback to the next provider in the chain, verified by a test
- [ ] A request with an injected PII string or prompt-injection pattern is caught by the Advance REGEX + ML + LLM based guardrails layer and rejected/redacted before reaching an agent node
- [ ] Repeating an identical or near-identical request within the cache TTL returns a cached response without a new LLM call
- [ ] `pytest` passes for graph routing, gateway fallback, and guardrails tests
- [ ] README documents setup, env vars, and how to run the pipeline locally
