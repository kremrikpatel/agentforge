## Objective
Build Phase 2 of "AgentForge": an Enterprise-grade RAG subsystem (hybrid search, reranking, HyDE, CRAG, Self-RAG, Text2SQL) that agent nodes from Phase 1 can call as a retrieval tool.

## Context (carry forward)
- Phase 1 delivered: LangGraph 4-agent pipeline (Analysis→Develop→Test→Deploy) in `agentforge/`, LLM gateway with Claude→GPT-4o→Groq fallback, guardrails layer, Redis STM, pgvector LTM, semantic caching, Docker Compose stack.
- Full platform vision includes later phases: connectors/actions, red-teaming, admin UI, instrumentation, K8s deploy — not in scope here.
- Backend is Python, orchestration is LangGraph, existing memory stack already uses Redis + Postgres/pgvector.

## Target State
A retrieval module agents can invoke that:
- Ingests documents into Qdrant (vector store) with metadata for hybrid search (dense + BM25/sparse).
- Reranks retrieved candidates with a cross-encoder before context assembly.
- Implements HyDE (hypothetical document embeddings) as an optional query-rewrite step.
- Implements CRAG (corrective RAG): grades retrieved chunks for relevance and triggers a fallback web-search or query-reformulation path when retrieval confidence is low.
- Implements Self-RAG: the generating agent can emit a "retrieve again" signal mid-generation if grounding is insufficient.
- Implements Text2SQL: natural-language queries against a defined Postgres schema, with a human-approval gate before any SQL executes.
- Exposes a single `retrieve(query, kb_id, mode)` interface the Phase 1 agent nodes can call as a LangGraph tool.
- Balances latency/cost: caching of embeddings and rerank scores, configurable top-k at each stage.

## Scope
- Work only in: `agentforge/rag/` (new), `agentforge/agents/` (only to add the retrieval tool binding, no rewriting existing node logic)
- Do NOT touch: `agentforge/gateway/`, `agentforge/guardrails/`, `agentforge/memory/` internals beyond importing what's needed

## Constraints
- Python 3.11+, Qdrant client, Postgres for Text2SQL target schema, reuse the existing LLM gateway module for any LLM calls (HyDE generation, CRAG grading, Self-RAG signal) — do not create a second gateway
- Text2SQL must never auto-execute — always return the generated SQL + a diff/preview for human approval first
- No new dependencies beyond Qdrant client, a cross-encoder reranker library, and what Text2SQL needs, without asking first
- Only make changes directly requested. Do not add features or refactor beyond what's asked.
