## Objective
Build Phase 7 of "AgentForge": production Kubernetes deployment (Docker + Helm) for the full stack, wired to Arize AI, LangWatch, and LangSmith observability.

## Context (carry forward)
- Full application exists from Phases 1–6: FastAPI backend, agent graph, RAG, actions, red-team suite, admin UI (separate frontend app), instrumentation/audit layer.
- Local dev currently runs via Docker Compose (from Phase 1) — this phase replaces/extends that for production K8s, it does not remove the Compose setup (keep it for local dev).
- Dependencies to run in-cluster: API service, frontend service, Redis, Postgres(pgvector), Qdrant.

## Target State
Production infra that:
- Has a Dockerfile per service (API, frontend, and any worker process for the red-team scheduler) — multi-stage builds, non-root user, minimal base images.
- Has a Helm chart (`agentforge/deploy/helm/`) with subcharts or values-driven config for: API deployment+service, frontend deployment+service, Redis (StatefulSet or managed-service values toggle), Postgres+pgvector (StatefulSet or managed-service values toggle), Qdrant (StatefulSet or managed-service values toggle), Ingress, ConfigMaps for non-secret config, and Secret templates (not actual secrets) for API keys/credentials.
- Includes resource requests/limits, liveness/readiness probes, and HPA (horizontal pod autoscaler) config for the API deployment.
- Wires OpenTelemetry-style tracing/metrics export from the API service to LangSmith (already used for judge scoring in Phase 1) and adds LangWatch and Arize AI integration points (SDK calls or exporters) around the agent execution core so every run is observable in all three tools.
- Provides `values-dev.yaml` and `values-prod.yaml` for environment-specific overrides (replica counts, resource sizing, external vs in-cluster datastores).
- Includes a README runbook: how to build/push images, `helm install`, rollback, and where to find dashboards in each monitoring tool.

## Scope
- Work only in: `agentforge/deploy/` (new — Dockerfiles + Helm chart), plus adding tracing/metrics hooks inside `agentforge/app/` and `agentforge/agents/` (instrumentation call sites only, not logic changes)
- Do NOT touch: `agentforge/rag/`, `agentforge/actions/`, `agentforge/redteam/`, `agentforge/instrumentation/`, `agentforge/web/` application logic

## Constraints
- Docker, Helm 3.x, target a standard K8s distribution (state the assumption, e.g. vanilla K8s 1.28+, no cloud-specific CRDs unless flagged)
- Secrets referenced via Kubernetes Secret objects populated externally (e.g. via `kubectl create secret` or a secrets manager) — never embed credential values in the chart or values files
- No new dependencies beyond what's needed for OTel/LangWatch/Arize SDK hooks, without asking first
- Only make changes directly requested. Do not add features or refactor beyond what's asked.

## Acceptance Criteria
- [ ] `docker build` succeeds for every service with a reasonable final image size
- [ ] `helm install --dry-run` validates cleanly against `values-dev.yaml` and `values-prod.yaml`
- [ ] Liveness/readiness probes and resource limits are set on every deployment
- [ ] HPA config present and validated for the API deployment
- [ ] A test pipeline run emits traces/metrics visible in the LangSmith/LangWatch/Arize integration points (mocked exporter check is acceptable if live accounts aren't available)
- [ ] README runbook covers build, deploy, rollback, and monitoring locations
- [ ] Existing Docker Compose local-dev setup still works unmodified

## Stop Conditions
Stop and ask before:
- Deleting any file
- Adding any dependency not listed in Constraints
- Embedding any credential value anywhere in the chart, values files, or Dockerfiles
- Touching anything outside the agreed scope, including any application logic beyond instrumentation call sites
