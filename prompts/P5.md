## Objective
Build Phase 5 of "AgentForge": an open-webui-style web frontend for configuring agents (instructions, knowledge, actions) and running/monitoring pipeline executions.

## Context (carry forward)
- Backend (Python/FastAPI) already exposes: `POST /pipeline/run` (Phase 1), RAG ingestion/retrieval (Phase 2), action registration/dispatch (Phase 3), red-team dashboard data (Phase 4).
- Instrumentation and K8s deploy are later phases, out of scope here.
- This phase is frontend-only; assume the above backend endpoints exist and are stable — extend the API only where a genuine gap exists (call it out, don't silently add scope).

## Target State
A web UI (open-webui-inspired: chat-style run view + settings panels) that lets an admin:
- Configure an agent: edit system instructions per pipeline stage (Analysis/Develop/Test/Deploy), attach knowledge bases (calls Phase 2 ingestion), attach available actions (calls Phase 3 registration).
- Trigger a pipeline run with a topic and watch live/streamed progress per stage (reuse Progress-style step reporting from the backend).
- View past runs, their per-stage outputs, and any guardrail interventions.
- View the Phase 4 red-team dashboard data inside the same app (embed or link).
- Basic auth-gated admin access (simple session-based auth is fine for this phase — full SSO/enterprise auth is a later concern, flag it rather than building it).

## Scope
- Work only in: `agentforge/web/` (new frontend app)
- Backend: only add new FastAPI endpoints if a required UI feature has no existing backend support — list any such additions explicitly before writing them
- Do NOT touch: `agentforge/agents/`, `agentforge/rag/`, `agentforge/actions/`, `agentforge/redteam/` internals

## Constraints
- Pick one stack and state it up front (e.g. a lightweight React+Vite SPA, or a server-rendered FastAPI+Jinja app) — do not mix frameworks
- Reuse existing backend endpoints wherever possible; new endpoints must follow the existing FastAPI patterns in the repo
- No new dependencies beyond the chosen frontend framework and an HTTP client, without asking first
- Only make changes directly requested. Do not add features or refactor beyond what's asked.

## Acceptance Criteria
- [ ] Admin can create/edit an agent config (instructions + knowledge + actions) and it persists
- [ ] Admin can trigger a run and see per-stage progress and final output in the UI
- [ ] Past runs are listable and viewable with full stage breakdown
- [ ] Red-team dashboard data is visible within the app
- [ ] Basic session-based auth gates the admin UI
- [ ] Any new backend endpoints have tests
- [ ] README documents how to run the frontend and which backend version it expects

## Stop Conditions
Stop and ask before:
- Deleting any file
- Adding any dependency not listed in Constraints
- Adding any backend endpoint beyond what's explicitly flagged as a gap
- Touching anything outside `agentforge/web/`
