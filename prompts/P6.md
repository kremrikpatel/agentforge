## Objective
Build Phase 6 of "AgentForge": production instrumentation that captures full execution trajectories for model training, plus PII filtering, audit logging, and action versioning for compliance.

## Context (carry forward)
- Full pipeline exists: agent graph (Phase 1), RAG (Phase 2), actions (Phase 3), red-team suite (Phase 4), admin UI (Phase 5).
- K8s/Helm deploy and observability wiring (Arize/LangWatch/LangSmith) is the next and final phase, out of scope here.
- Guardrails module (Phase 1) already does inline PII/injection checks — this phase adds structured logging/audit on top, not a second guardrails system.

## Target State
An instrumentation and compliance layer that:
- Captures a structured trajectory per pipeline run: every reasoning step, tool/action call (input, output, latency, success/failure), and any guardrail intervention — stored in a queryable format (Postgres table or append-only log, your call, state the choice).
- Captures implicit reward signals: resolution success/failure, whether the run required escalation/human intervention, and any explicit user feedback if provided — schema designed for future export to a training pipeline (define the export schema even if the actual ML pipeline doesn't exist yet).
- Adds a PII filtering pass on trajectory data before it's persisted (separate from the inline request-time guardrails) so stored training data itself is scrubbed.
- Adds audit logging: every admin action (agent config change, action registration, knowledge base edit) is logged with who/what/when/before-after diff.
- Adds action versioning: changes to a registered action (Phase 3) or agent config are versioned, with rollback to a prior version supported.
- Exposes a `GET /trajectories/{run_id}` and `GET /audit-log` endpoint for inspection (admin-auth gated, reusing Phase 5's auth).

## Scope
- Work only in: `agentforge/instrumentation/` (new), `agentforge/actions/` and `agentforge/agents/` (only to add versioning hooks, not rewrite logic)
- Do NOT touch: `agentforge/rag/`, `agentforge/redteam/`, `agentforge/web/` frontend code (backend endpoints only)

## Constraints
- Python 3.11+, reuse existing Postgres connection and guardrails PII-detection logic where possible rather than duplicating it
- Trajectory and audit data must be scrubbed of PII before persistence — this is a hard requirement, not best-effort
- No new dependencies beyond what's needed for structured logging/versioning, without asking first
- Only make changes directly requested. Do not add features or refactor beyond what's asked.

## Acceptance Criteria
- [ ] A full pipeline run produces a persisted trajectory with all steps, tool calls, and timings
- [ ] A trajectory containing injected PII in tool output is scrubbed before storage (test included)
- [ ] Admin config changes appear in the audit log with correct before/after diff
- [ ] Editing a registered action creates a new version; rollback to a prior version works and is tested
- [ ] `GET /trajectories/{run_id}` and `GET /audit-log` return correct, auth-gated data
- [ ] `pytest` passes for scrubbing, versioning, and rollback
- [ ] README documents the trajectory schema and how it maps to future training data export
